# P3.1 — Shared single memos daemon: implementation spec (2026-05-27)

**Goal:** retire per-gateway `bridge.cts` instances. Today each of the 8 gateways spawns its own
`bridge.cts` that **cold-loads BGE-large (~2 cores) and opens the DB** — N agents = N full memos
cores. Make the gateways **thin HTTP clients of the one `:18800` daemon** so there is exactly ONE
memos core / ONE model in memory. This is the structural fix the P1.2 flock and P1.1 backgrounding
only *mitigate*; landing P3.1 **removes the P1.2 boot-lock** and makes boot-spiral impossible.

## Why it's now feasible (two enablers already shipped)
1. **Per-request namespace** (plugin patch #2): `X-As-Profile` header / `?as_profile=` → an
   AsyncLocalStorage namespace context (`runWithRequestNamespace`, `effectiveNamespace`). The daemon
   is already multi-tenant per request — a single daemon can serve all 8 profiles, each request
   carrying its own `(agent_kind, profile_id)`. **This is the linchpin.**
2. **`--daemon` mode does its own LLM** (`bridge.cts`: `hostLlmBridge = args.daemon ? null : …`).
   So the shared daemon uses its own configured DeepSeek for capture/reward — **no `host.llm.complete`
   callback to the gateway is needed** (today's stdio bridges call back into Hermes for LLM; the
   shared daemon doesn't, which simplifies the transport rewrite).

## Current vs target
- **Current**: gateway → `daemon_manager.ensure_bridge_running()` spawns `bridge.cts` → `MemosBridgeClient`
  speaks JSON-RPC over **stdio** (`session.open`, `turn.start`, `turn.end`, `memory.search`, …).
  `:18800` is a *separate* `bridge.cts --daemon` (HTTP, viewer + reads + `GET /api/v1/memory/search`).
- **Target**: gateway → `HttpMemosClient` → the ONE `:18800` daemon over HTTP, passing its namespace
  per request. No per-gateway bridge spawn. The daemon owns the only core + model.

## Gap analysis (what HTTP already exposes vs. what's missing)
- ✅ Already HTTP: `GET /api/v1/memory/search|policy|trace|world`, `diag`, `episodes`, `health`, reads.
- ❌ Missing (currently stdio-only — the capture WRITE path): `session.open`, `turn.start`, `turn.end`
  (and the lite-capture / `subagent.record` equivalents). **These are the new endpoints to add.**

## Work items
1. **Daemon: expose the capture write RPCs over HTTP.** Add authenticated `POST /api/v1/turn/start`,
   `POST /api/v1/turn/end`, `POST /api/v1/session/open` (+ a `recall`/prefetch that maps to the existing
   `turn.start` retrieval). Each handler runs inside `runWithRequestNamespace(headerNamespace)` so the
   write lands in the caller's namespace. Reuse the same core methods the stdio bridge dispatches to
   (`memory-core` handlers) — this is *route plumbing*, not new logic. Files: `server/http.ts`,
   `server/routes/*` (new `turns.ts`), wiring to `core/pipeline/memory-core.ts`.
2. **Auth for the adapter.** The HTTP API is password-gated (viewer). The adapter calls loopback only,
   so add an **internal loopback bypass** (or a per-boot shared token written to a 0600 file the daemon
   + adapter both read) for the `/api/v1/turn/*` + `/session/*` routes. Must NOT widen external access
   (bind stays 127.0.0.1; the bypass is loopback-gated). Files: `server/http.ts` auth middleware.
3. **Adapter: new HTTP transport.** Add `http_client.py` (mirrors `bridge_client.py`'s surface:
   `open_session`, `turn_start`, `turn_end`, `search`) speaking HTTP to `:18800` with the namespace
   header + internal token. In `memos_provider/__init__.py`, select transport by a flag
   (`MEMOS_TRANSPORT=http|stdio`, default `stdio` during rollout). `daemon_manager` becomes
   "ensure `hermes-memos-daemon.service` is up" (systemctl), not "spawn a bridge". The `bridge_boot_lock`
   (P1.2) is removed on the HTTP path. Files: `adapters/hermes/memos_provider/{__init__.py,http_client.py,daemon_manager.py}`.
4. **Namespace correctness.** Each gateway passes `X-As-Profile: <profile>` (its
   `_runtime_namespace().profileId`) on every call. Verify private traces still land under the right
   profile and stay private (the whole point of isolation).
5. **Remove the host-LLM callback path on HTTP** (daemon self-serves LLM); keep it for the stdio path
   until stdio is retired.

## Migration / rollback
- Ship behind `MEMOS_TRANSPORT` (default `stdio`). Flip ONE gateway to `http`, verify capture +
  isolation + a real trace lands under its profile, then roll the rest. Keep stdio code until all 8
  run on HTTP for a week. Rollback = flip the env var.

## Risks
- **Single point of failure**: one daemon serves all 8. Mitigated — it's already `hermes-memos-daemon.service`
  (Restart=always, enabled), and P1.1 makes its boot non-blocking.
- **Auth bypass scope**: must stay loopback-only; do not expose capture writes to the tailnet.
- **Concurrency**: one core serializes 8 gateways' writes (SQLite WAL already serializes). Capture is
  async/background, so added latency is off the user's reply path. Watch the event-loop responsiveness
  (same single-thread caveat as P1.1) — if heavy, move reflection to a worker thread.
- **Namespace leak**: a missing/incorrect `X-As-Profile` would cross-contaminate. Add a server-side
  assert that capture writes require an explicit namespace header on the internal routes.
